# Song PDF (lyrics sheet) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A song can carry an optional lyrics PDF, attached in the three song editors (online and offline on native), and the live view shows the score image, the PDF, and the typed lyrics stacked in that order, rendered with pdf.js.

**Architecture:** Pure logic (validation, block selection, offline overlay, cache backfill) is unit-tested with Vitest. The PDF is a new nullable `songs.pdf_url` column, uploaded through a new Vercel Blob route that mirrors the image route, and queued offline through the same local store and resolution map the image already uses. The live view selects the present blocks with a pure function and renders them in one scrolling column; the PDF block loads pdf.js on the client only.

**Tech Stack:** Next.js (App Router, static export for native), Drizzle + Postgres (neon-http), Vercel Blob client uploads, Capacitor, Vitest, daisyUI, `pdfjs-dist` (pinned exact version).

**Spec:** `docs/superpowers/specs/2026-11-17-song-pdf-design.md`

## Global Constraints

- PDF size ceiling: `10 * 1024 * 1024` bytes (10 MB), same as the image.
- PDF content type: exactly `application/pdf`.
- PDF rendering renders at most the first **50 pages**.
- Block order is always `image`, `pdf`, `lyrics`.
- Greek user-facing copy: `Στίχοι σε PDF`, `Αφαίρεση PDF`, `Το PDF δεν φορτώθηκε.`, `Μη υποστηριζόμενος τύπος αρχείου. Επιτρέπεται μόνο PDF.`, `Το PDF ξεπερνά το όριο των 10MB.`
- `pdfjs-dist` is pinned to an exact version (the newest stable at Task 8 time, see Task 8 step 1).
- Offline PDF viewing is out of scope (online only, same as the score image).

## Review Focus

1. **Corrupt or unreachable PDF URL** — the live view shows `Το PDF δεν φορτώθηκε.` and the typed lyrics still render below it, never a blank screen. Tested in Task 8 (component-level manual check plus `selectStackBlocks` keeps `lyrics` when the PDF is present).
2. **Empty string as a URL** (`pdfUrl: ''`) — treated as absent, not as a block. Tested in Task 2.
3. **Remove PDF while an offline upload is still queued** — the queued upload must not be orphaned; removing sets `pdfUrl: null` and clears `pendingPdfBlobId`, and the earlier queued write still uploads. Tested in Task 6 (`songsMerge` overlay) and the manual checklist.
4. **Very long PDF (many pages)** — rendering stops at 50 pages and says so. Tested in Task 8 (`MAX_PDF_PAGES` constant asserted in a unit test for the page-count helper).
5. **Image-only or lyrics-only song** — exactly the existing behavior (one block fills the view). Tested in Task 2 by the single-block cases.

import { describe, it, expect } from 'vitest';
import { selectStackBlocks, MAX_PDF_PAGES } from './stackBlocks';

describe('selectStackBlocks', () => {

  it('returns one block alone (fills the view)', () => {

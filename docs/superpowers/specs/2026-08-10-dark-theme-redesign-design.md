# Σκοτεινό θέμα (dark theme) — Design

## Πλαίσιο και πρόβλημα

Το Glentify είναι σήμερα κλειδωμένο σε ένα ενιαίο, ανοιχτόχρωμο daisyUI theme (`corporate`), ανεξάρτητα από τις ρυθμίσεις του λειτουργικού/browser — επιλογή που έγινε σκόπιμα ώστε η mobile εφαρμογή να είναι ευανάγνωστη πάνω στη σκηνή. Ο χρήστης θεωρεί πλέον αυτό το look «πολύ απλό» και «παλιό» και θέλει κάτι πιο μοντέρνο.

Μετά από οπτική δοκιμή τεσσάρων κατευθύνσεων (ρεμπέτικο/ζεστό, σκοτεινό στιλ σκηνής, γιορτινό, μίνιμαλ) και δύο γύρων επιλογής απόχρωσης, επιλέχθηκε: **σκοτεινό φόντο + teal accent**.

## Στόχος

- Αντικατάσταση του τρέχοντος locked light theme με ένα νέο locked dark theme, χωρίς δυνατότητα εναλλαγής — παραμένει «μία εμπειρία» σκόπιμα, όπως και σήμερα, απλά αλλάζει ποια είναι αυτή η εμπειρία.
- Εφαρμογή **παντού**: native (Android), web, και admin σελίδες — μία συνεπής ταυτότητα σε όλο το app.
- Οπτική αναβάθμιση πέρα από το χρώμα (πιο στρογγυλεμένες γωνίες σε κουμπιά/κάρτες) ώστε να αισθάνεται πραγματικά πιο μοντέρνο, όχι απλά «το ίδιο σε σκούρο».
- Διατήρηση της αναγνωσιμότητας/αντίθεσης που είχε η αρχική σχεδιαστική απόφαση (ευανάγνωστο πάνω στη σκηνή) — ένας σκοτεινός καμβάς είναι εξίσου έγκυρος για αυτόν τον στόχο (λιγότερη λάμψη σε σκοτεινό μαγαζί/σκηνή σε σχέση με λευκή οθόνη), αρκεί η αντίθεση κειμένου/στοιχείων να παραμείνει υψηλή.

## Εκτός εμβέλειας

- Δυνατότητα εναλλαγής light/dark (ρητά απορρίφθηκε).
- Αλλαγή γραμματοσειράς, εικονιδίων/εικόνων, ή αναδιάρθρωση layout οποιασδήποτε σελίδας.
- Οτιδήποτε άλλο από τα 4 νέα features που συζητήθηκαν (offline δημιουργία/sync-back, admin tool στο Android, διαμοιρασμός προγραμμάτων) — αυτά θα σχεδιαστούν ξεχωριστά.

## Τεχνική προσέγγιση

Ολόκληρος ο κώδικας χρησιμοποιεί ήδη αποκλειστικά τις σημασιολογικές κλάσεις του daisyUI (`btn`, `card`, `bg-base-200`, `alert`, κ.λπ.) — επιβεβαιώθηκε με αναζήτηση: μηδέν hardcoded χρώματα (`bg-white`, `text-black`, hex literals) σε `src/app` ή `src/components`. Αυτό σημαίνει ότι η αλλαγή μπορεί να είναι **αμιγώς αλλαγή theme**, χωρίς να αγγίξει κανένα από τα ~30 αρχεία σελίδων/components.

Η αλλαγή γίνεται αποκλειστικά στο `src/app/globals.css`, αντικαθιστώντας:

```css
@plugin "daisyui" {
  themes: corporate --default;
}

:root {
  color-scheme: light;
}
```

με ένα νέο custom daisyUI 5 theme (μορφή token-based, όπως τα built-in dark themes του daisyUI — π.χ. `night`, `dim`):

```css
@plugin "daisyui" {
  themes: glentify-dark --default;
}

:root:has(input.theme-controller[value=glentify-dark]:checked), [data-theme="glentify-dark"] {
  color-scheme: dark;
  --color-base-100: #14141c;
  --color-base-200: #1c1f26;
  --color-base-300: #262a33;
  --color-base-content: #e5e7eb;
  --color-primary: #0d9488;
  --color-primary-content: #ffffff;
  --color-secondary: #262a33;
  --color-secondary-content: #e5e7eb;
  --color-accent: #0d9488;
  --color-accent-content: #ffffff;
  --color-neutral: #1c1f26;
  --color-neutral-content: #e5e7eb;
  --color-info: #38bdf8;
  --color-info-content: #06202e;
  --color-success: #34d399;
  --color-success-content: #052e21;
  --color-warning: #fbbf24;
  --color-warning-content: #2e1e02;
  --color-error: #f87171;
  --color-error-content: #2e0a0a;
  --radius-selector: 1rem;
  --radius-field: 0.75rem;
  --radius-box: 1.25rem;
  --border: 1px;
  --depth: 0;
  --noise: 0;
}
```

(Ακριβείς αποχρώσεις μπορούν να μικροφινετιστούν στο implementation task κατά το manual visual pass, χωρίς να αλλάξει η προσέγγιση.)

Το σχόλιο πάνω από το `body { font-family: ... }` που εξηγεί το «locked theme» σκεπτικό ενημερώνεται ώστε να αντανακλά το νέο σκοτεινό θέμα αντί για το παλιό ανοιχτόχρωμο.

## Δοκιμές

Δεν υπάρχει testable λογική (καθαρό CSS). Επαλήθευση:
- `npm run build` ολοκληρώνεται καθαρά.
- Χειροκίνητο οπτικό πέρασμα σε native (Android), web, και admin σελίδες: αναγνωσιμότητα κειμένου σε σκούρο φόντο, αντίθεση στα κουμπιά (ειδικά λευκό κείμενο πάνω σε teal), ευκρίνεια πεδίων φόρμας στις πυκνές admin CRUD σελίδες (δημιουργία/επεξεργασία τραγουδιού, προγραμμάτων), απουσία «λευκής αναλαμπής» (flash) του παλιού θέματος κατά τη φόρτωση.
